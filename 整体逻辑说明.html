S4

编排优化（Orchestration）

文件：s4_orchestrator.py   模块：M2-07

三层叙事结构

层级角色图表类型叙事优先级
L1 结论层总览核心指标KPI卡1（最高）
L2 佐证层趋势/对比论证折线、柱状、地图2
L3 明细层分布/明细深入饼图、散点、表格、热力图3

编排三步

步骤操作规则
1. KPI挑选选择最有价值的KPI卡按金额>笔数>其他排序，最多4个
2. 去冗余相似图表合并/删除图表签名相似度 > 0.8 时只保留1个
3. 叙事排序按三层叙事排列kpi→line/bar→pie/scatter/table

图表签名相似度计算

签名格式: "{chart_type}:{x_field}:{y_field}"
相似度 = 匹配的部分数 / 3
> 0.8 时判定为冗余，保留优先级高的
输出：编排后的图表列表（≤6个）+ 三层分组 + 叙事流向（结论→佐证→明细）
S5

评分验证（Score Card）

文件：s4_orchestrator.py (S5ScoreCard类)   模块：M2-08

三维度评分卡

维度权重评分逻辑满分条件
冗余度30%1 - (相似图表对数/总对数)无任何相似图表=100
覆盖度40%覆盖类型数 / 期望类型数覆盖kpi+line+bar+pie=100
叙事性30%图表位置 vs 期望叙事层级的匹配度所有图表在正确叙事层=100

总分 = 冗余度×0.3 + 覆盖度×0.4 + 叙事性×0.3

通过标准：≥ 70分 通过。不通过时最多重排 3次。

重排策略（R2返工修正）

重排次数策略操作
第1次按叙事优先级重排kpi→line→bar→pie→table
第2次补充缺失类型从备选池取，不足时自动生成默认图表
第3次删除冗余相似图同类型同字段的图表去重
改进建议生成：冗余度<80分提示"合并相似图表"；覆盖度<80分提示"缺少XX类型"；叙事性<70分提示"按KPI→趋势→明细排序"。

① 意图分类（Intent Classification）

文件：intent_classifier.py   模块：M3-01

7类意图 + 正则匹配 + LLM兜底

意图类型正则模式示例参数提取
change_chart 换图(换|改|变成).{0,5}(图|饼图|柱图...)source_type, target_type
add_chart 新增图(新增|添加|加|插入).{0,5}(图|图表)chart_type

edit_title 标题编辑(改|修改|编辑).{0,5}(标题|名字)new_title

分类流程

  1. 正则匹配：依次匹配7类意图模式，命中即返回
  2. 置信度计算：基础分70 + 关键词密度加分(≤20) + 动作词加分(≤5)，上限95
  3. LLM兜底：规则匹配失败时调用LLM分类（返回JSON）
  4. 未知意图：LLM也失败则返回UNKNOWN，引导用户示例
置信度阈值：≥ 70分 标记为 is_confident=True，低于70分的意图不会执行动作（仅回复理解结果）。

② 可行性检查（Feasibility Check）

文件：feasibility_checker.py   模块：M3-03

三级严重度（Severity）

Blocking 阻断

阻断执行，用户必须修改需求或强制覆盖

检查项：粒度不匹配、字段缺失、图表超限、删除最后一张图

Warning 告警

允许执行但提示风险

检查项：预测功能数据不足

Info 建议

优化建议，不阻断

检查项：有日期字段时建议折线图而非饼图

检查维度

检查项适用动作检查逻辑默认严重度
数据粒度检查filter_drill, change_chart, add_chart用户要月度但数据只有年度 → 阻断Blocking
字段存在性检查filter_drill, attribution, change_chart, add_chart用户提到"区域"但数据无此字段 → 阻断Blocking
图表数量检查add_chart已有≥10个图表 → 阻断Blocking
删除保护检查delete_chart仅剩1个图表时 → 阻断Blocking
图表类型合理性change_chart有日期字段时用饼图 → 建议Info

③ 用户优先级Override机制（本次实现）

核心原则：用户需求最高优先级

当用户需求与系统约束冲突时（如AI推荐饼图但用户要折线图），blocking级问题允许用户强制覆盖，降级为warning后执行。

后端实现（feasibility_checker.py）

参数类型说明
override_blockingbool当为True时，blocking级问题降级为warning，允许执行
# override逻辑
if override_blocking and blocking_issues:
    # blocking降级为warning
    overridden_issues = [
        {**issue, "original_severity": "blocking", "severity": "warning"}
        for issue in blocking_issues
    ]
    issues = warning_issues + overridden_issues
    feasible = True  # 覆盖后视为可行

API层实现（chat.py）

SSE事件字段说明
feasibility_check_failedcan_override是否存在可覆盖的blocking问题
请求模型override: bool用户选择强制执行时设为True
响应增强overridden_issues被覆盖的约束列表，在回复中提示用户

组件行为
