# ev_35 — 3.5 AI 只会说"刷新试试"（修：让它能实查）

## 一、问题定位
`backend/app/core/action_executor.py::_execute_attribution`（归因追问）在 2026-09-17 已从"编造假血缘"改为"诚实罗列 3 条可能性"，但结尾仍是：

> "请先刷新看板页面，若仍为空请按上述路径排查。"

即：**AI 什么都没查，把排查成本甩给用户**——这就是"AI 只会说刷新试试"的体感来源。

## 二、为什么能实查（关键设计决策）
用户原话是"调 chart-data 检查"。实测后发现**不必走 HTTP**：

| 数据源 | 是否可用 | 说明 |
|---|---|---|
| `context["dataset_info"]["field_profiles"]` | ✅ | 消息链路 `chat.py:533` 构建，含**真实字段名 + null_count/null_rate** |
| `context["field_profiles"]` | ✅ | 会话链路 `chat.py:359` 构建（扁平写法，同一份数据） |
| `current_config["charts"]` | ✅ | `chat.py:490` = `dashboard.config`，含每张图的 x/y/category 字段 |
| HTTP 调 `/datasets/{id}/chart-data` | ❌ 不用 | `_execute_attribution` 是**同步**静态方法，发起 HTTP 需改异步/线程池（即 N2 里的 `asyncio.run` 反模式）；且字段画像已在 context 里，**直接用真实数据更轻更准** |

→ 结论：用 context 内真实字段画像实查，等价于"查数据"，且不引入异步风险。**单文件可完成**。

## 三、修复实现（`action_executor.py` 单文件）

### 1. 取真实字段画像（兼容两种 context 约定）
```python
fps = (((context or {}).get("dataset_info") or {}).get("field_profiles")
       or (context or {}).get("field_profiles") or [])
field_index = {fp["name"] or fp["column"]: fp for fp in fps}
```
> 注意：`action_planner._field_names` 只读嵌套写法，而 `chat.py:359` 是扁平写法 —— **两种约定并存**，故都兼容（用例5 专门验证）。

### 2. 定位目标图表
标题或字段命中 `target` → 否则取"字段缺失的那张最可疑图" → 否则取第一张非 KPI 图。

### 3. 逐字段判定（4 类结论）
| 判定 | 条件 | 结论 | 下一步建议 |
|---|---|---|---|
| `missing` | 字段不在字段画像里 | "不在主数据集 N 个字段里（现有字段如：…）" | 按字段匹配到对应数据集／告知正确字段名重建 |
| `emptied` | `null_rate ≥ 0.999` | "存在但空值率 100%（质检清洗后置空）" | 回质检撤销/调整该列清洗规则 |
| `high_null` | `null_rate ≥ 0.5` | "存在但空值率偏高（>50%）" | 先做缺失值处理再重画 |
| `ok` | 存在且非空 | "字段层面没问题" | 更可能是配置/取数问题 → 重建图表 |

### 4. 兜底：不能实查时**说明原因**，而不是让刷新
无字段画像 → "当前会话没有携带该数据集的字段画像…我无法在这里实查字段是否存在——这也是我不直接说「刷新试试」的原因：没有依据的结论没有价值。"

### 5. 结构化回传
新增返回字段 `check_result`（`checkable / chart / fields{字段:判定} / field_count`），便于前端展示与日志追踪。

## 五、边界覆盖
- 两种 context 约定（嵌套/扁平）→ 用例5
- 无字段画像 / 无图表 / 无匹配图表 → 各自独立分支，均不说"刷新试试"
- 图表无任何字段 → "这张图没有配置任何字段"
- `null_rate` 缺失或非数字 → `try/except` 兜底为 0
- 字段画像条目非 dict → 跳过
- KPI 图不参与"可疑图"定位（KPI 无 x/y 字段）

## 六、未改动的相关项（说明为什么不用改）
- `_execute_chart_fix`（:1267）：**本身就是真诊断**（定位图表 → 取 dataset_id → 查字段 → 真执行清洗修复），不是话术，无需改。
- `action_executor:1223/1236/1318` 里的"刷新"：是**真的执行了清洗修复后**让前端重新取数，属正常语义，保留。
- `brain_run_sse:1426/1509` 的"稍后刷新"：流水线状态提示，非对话兜底，保留。
