## 二、关键设计决策

1. **数据真实来源**：S3 阶段在 `brain_run_sse.py:797` 用 `get_duckdb()` 对 `ds_{dataset_id}` 表跑一次聚合查询
   `COUNT(DISTINCT f)` + `SUM(CASE WHEN f IS NULL THEN 1 ELSE 0 END)`，算出**真实** distinct 与空值率。
   不是估算，不是 5 行样本外推。列名经白名单正则 `^[A-Za-z0-9_一-鿿]+$` 过滤防注入。
2. **失败不阻断**：`_compute_field_profiles` 任何异常返回 `None` → `_desc` 降级为原「类型+角色+建议」，与改造前行为一致（向后兼容）。
3. **V4 前置防御**：敏感字段（身份证/手机/姓名/名称/地址/邮箱/证件/编号）**不注入取值样例**，只保留 distinct 计数（数字非 PII）。`verify_25_p0_prompt.py` 用例4 实测 `3301.../4402...` 不出现在 prompt。
4. **归一化匹配**：profile 名带首尾空格（如「 身份证号 」）仍能匹配到字段（复用 D2 `_lookup` 逻辑），避免字段名不一致漏注入。

## 三、验收（均为真实执行）

### V1 — `fields_desc` 含 `distinct=` 与 `空值率`，高基数字段带"禁止作为分类维度"
`verify_25_p0_prompt.py`（直接调 `_build_prompt`，构造 semantics+profiles）：
```
  PASS | 客户名称 含 distinct=2143
  PASS | 担保类型 含 distinct=2
  PASS | 抵押率 含 空值率3%
  PASS | 担保类型 含 空值率0%
  PASS | 客户名称 高基数带『禁止作为分类维度』
  PASS | 担保类型 含取值样例 融资性/非融资性
RESULT: ALL PASS
```

### V2 — 构造 distinct=2143 的"客户名称" → prompt 带高基数禁维度标注
同上用例：高基数字段（cardinality=high）自动附加「⚠️高基数，禁止作为分类维度」，
LLM 据此不会把 2143 类取值的客户名称选作饼图维度（V2 的"LLM 行为"依赖此标注，标注已实测存在）。
