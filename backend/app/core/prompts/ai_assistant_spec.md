# AI对话调整图表 - 产品与AI协同逻辑规范

## 一、核心原则：AI是参谋，用户是司令

```
用户优先级 > AI推荐 > 规则矩阵
```

- **用户明确指令**：直接执行，不校验规则矩阵
- **AI推荐**：LLM生成建议，用户可接受或拒绝
- **规则矩阵**：仅用于初次生成的兜底和建议，用户一旦介入自动失效
- **离谱需求**：AI必须引导澄清，不可盲目执行

---

## 二、AI必须理解的全链路数据加工逻辑

### 2.1 六层数据血缘架构

AI必须知道每一层是什么、能做什么、不能做什么：

```
原始数据层     → 用户上传的原始文件（Excel/CSV），不可修改
字段标准化层   → 字段名统一、类型转换
数据清洗层     → 去重、空值填充、格式修正、异常值处理
业务加工层     → 业务规则计算（如抵押率、风险敞口）
聚合计算层     → 汇总、分组、统计（KPI、趋势、分布）
看板输出层     → 最终呈现的图表和看板
```

### 2.2 AI的边界认知

AI必须知道以下约束，并在用户需求超出时引导澄清：

| 用户需求 | AI判断逻辑 | 结果 |
|---|---|---|
| "做月度汇总" | 检查数据粒度：如果数据只有年度，无法生成月度 | 引导："当前数据是年度粒度，无法按月汇总，是否按年展示？" |
| "按客户维度分析" | 检查字段是否存在"客户"相关字段 | 引导："数据中没有客户维度字段，可用的维度有：{字段列表}" |
| "预测下季度数据" | 检查是否有时间序列+足够历史数据 | 数据不足时引导："数据量不足以做预测，建议补充历史数据" |
| "把饼图改成折线图" | 饼图无时间维度，但折线图需要x轴为时间 → 自动适配字段 | 直接执行，字段映射自动调整 |
| "删除这个图表" | 确保看板至少保留一个图表 | 只剩一个时拒绝并提示 |

### 2.3 AI的认知来源

AI在对话时加载以下上下文：

```
1. 数据集元数据：字段名、字段类型、行数、数据粒度
2. 看板配置：当前图表列表、类型、标题、字段映射
3. 数据血缘：各层数据来源和加工链路
4. 规则矩阵：可用的图表类型和触发条件
```

## 三、自然语言对话调整图表完整流程

```
用户输入
  │
  ▼
┌─────────────── 意图分类 ───────────────┐
│  1. 规则匹配（关键词+正则，5类意图）       │
│     - 置信度≥70 → 直接走执行             │
│     - 置信度<70 → LLM兜底分类            │
│       - LLM成功 → 走执行                 │
│       - LLM失败 → 返回引导建议            │
└──────────────────┬────────────────────┘
                   │
                   ▼
┌─────────────── 可行性检查 ──────────────┐
│  AI检查：用户需求是否可执行？              │
│  ├─ 数据粒度是否支持？                    │
│  ├─ 字段是否存在？                       │
│  ├─ 图表类型是否合理？                    │
│  └─ 数量限制是否满足？                    │
│                                         │
│  不可行 → AI引导澄清 ⚠️                 │
│  可行 → 继续执行                         │
└──────────────────┬────────────────────┘
                   │
                   ▼
┌─────────────── 动作执行 ────────────────┐
│  ActionExecutor执行配置变更              │
│  不经过规则矩阵，直接修改                 │
└──────────────────┬────────────────────┘
                   │
                   ▼
┌─────────────── 视觉评估 ────────────────┐
│  规则评估：图表数/类型多样性/饼图切片等     │
│  仅告警，不阻断                           │
└──────────────────┬────────────────────┘
                   │
                   ▼
┌─────────────── SSE回传前端 ─────────────┐
│  → 局部重渲染（不刷新整个页面）            │
│  → 推荐追问 3个                          │
│  → 记录用户事件到飞轮日志                  │
└─────────────────────────────────────────┘
```

## 四、AI引导与反馈机制（用户需求离谱时）

### 4.1 可行性检查矩阵

```
用户说"做月度汇总" 
  → AI查：数据粒度 = "年" 
  → 结果：不可行 ❌
  → AI回应："当前数据是年度粒度，无法按月汇总。 
     建议：①按年展示 ②补充月度数据后再分析"
```

```
用户说"预测下季度趋势"
  → AI查：数据量 = 3条记录
  → 结果：不可行 ❌
  → AI回应："数据量较少(仅3条)，预测结果可能不准确。
     建议：①补充更多历史数据 ②仅展示当前趋势"
```

```
用户说"筛选华东地区数据"
  → AI查：字段中存在"区域"、"华东"
  → 结果：可行 ✅
  → AI执行：直接筛选
```

### 4.2 引导话术规范

| 场景 | AI引导话术 |
|---|---|
| 数据粒度不支持 | "当前数据粒度是{级别}，无法按{用户要求}分析，是否改为{可用方案}？" |
| 字段不存在 | "数据中没有'{字段名}'字段，可用的维度有：{列表}" |
| 图表类型不合理 | "该数据更适合{推荐类型}，是否改为{推荐类型}？" |
| 数量超限 | "看板已有{数量}个图表，建议删除或合并后再新增" |
| 需求模糊 | "您说的是？请更具体描述，例如：按区域筛选、按时间趋势、按类别对比" |

## 五、AI与规则引擎的协同分工

| 阶段 | 规则引擎职责 | AI职责 | 谁主导 |
|---|---|---|---|
| 初次生成 | 字段分析+主题匹配+图表推荐 | 兜底主题识别+LLM推荐 | 规则引擎 |
| 对话调整 | 无（不参与） | 意图分类+可行性检查+参数提取 | AI |
| 可行性检查 | 无 | 数据粒度/字段/数量检查 | AI |
| 动作执行 | 无 | 配置变更+字段映射 | AI |
| 视觉评估 | 规则评估（不阻断） | 无 | 规则引擎 |
| 飞轮采集 | 无 | 记录用户偏好 | AI |
