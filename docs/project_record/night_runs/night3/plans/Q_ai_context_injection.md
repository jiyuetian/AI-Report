# 方案 Q · AI 上下文与材料注入（★ 核心）

> 目标：把给 LLM 的"上下文"从**当前随手拼的一段字符串**，变成**分层、可控、可度量、可运营的材料体系**。
> 一句话原理：**AI 选错字段，往往不是模型笨，是我们没告诉它字段里到底装了什么。**

---

## 一、现状（已核实）

### 1.1 各阶段现在给了 LLM 什么

| 阶段 | prompt 构造位置 | 注入的内容 |
|---|---|---|
| S1 主题识别 | `s1_theme_detector.py:169-183` | 字段名 + 数据集名 + 主题候选 + **样本前 3 行**（`str(...)[:500]`） |
| S2 目标生成 | `s2_goal_generator.py:234-242` | theme / grain / fields / base_goals / **sample_data[:3]** |
| **S3 图表推荐** | `s3_llm_enhancer.py:315-358` | 主题 + `fields_desc` + 维度建议 + 粒度 + 目标 + 派生指标口径 + 错误回写 + 系统护栏 |
| S4b 分析说明 | `brain_run_sse.py:965-983` | 图表摘要[:6] + 目标[:5] + **prompt 内联硬编码**（唯一未外置的） |
| AI 质检 | `ai_quality_checker.py:56` | **样本 50 行**（`max_rows=50`） |

### 1.2 `fields_desc` 到底长什么样（关键）

`s3_llm_enhancer.py:291`：
```python
fields_desc = "\n".join(f"  - {f}（{_desc(f)}）" for f in fields)
# _desc = 类型标签 + business_role + chart_hint
# 例：  - 地区（分类维度(适合做分布/对比/占比)，地区维度，建议:地区对比）
```

**只有「字段名 + 类型标签 + 业务角色 + 建议」，没有：**
- ❌ 真实取值（这个字段里到底有哪些值）
- ❌ 基数（distinct 多少个）
- ❌ 空值率
- ❌ 样本行

已确认 `s3_llm_enhancer.py` 全文**不含 `sample` 字样** —— S3 是唯一完全不注入样本数据的 AI 阶段。

### 1.3 由此导致的三个具体问题

| 问题 | 机理 |
|---|---|
| **P1 臆造字段名** | LLM 只看到"担保金额（数值）"，不知道还有"抵押率"是算出来的，于是自己拼 `贷款金额_分桶`。现有 prompt 第 6 条（:338）已经在**用文字警告**这件事，说明这是高频问题——**靠警告约束，不如直接给真相** |
| **P2 基数病态** | LLM 不知道"客户名称"有 2000 个不同值，拿它做饼图。这正是方案 P 的 L2 要拦的问题 —— **源头给信息，比事后拦截更划算** |
| **P3 编造筛选值** | LLM 不知道"担保类型"的取值是 `["融资性","非融资性"]`，可能生成"按担保类型=政策性筛选"这类不存在的值 |

### 1.4 其他现状

- **无 RAG / 向量库 / embedding** —— 全仓确认不存在
- **材料来源仅三处**：主题词典（`brain_configs.theme_dict`，`brain_v2.py:348-357`）、
  外置 prompt（`backend/app/core/prompts/*.md` 12 个文件，`prompt_loader.py:28`，可被 Prompt 中心覆盖）、
  派生指标口径（`derived_metric_service`）
- **上下文长度控制 = 粗暴截断**：`sample_data[:3]`、`str(...)[:500]`、`final_charts[:6]`、`goals[:5]`
- **TokenBudget 只熔断不压缩**：`brain_run_sse.py:346-382`，80% 告警、100% 直接跳过 S4b
- **token 是估算值**：`llm_gateway.py:163-168` 按 `len/4` 粗估

## 二、方案设计：材料五层 + 注入策略 + 预算管理

```
L4 反馈记忆  自愈错误 / 用户修改 / 历史被剔除的图      （可裁剪，最先丢）
L3 数据样本  代表性样本行（脱敏后）                    （可裁剪）
L2 数据画像  字段：类型 + 基数 + 空值率 + 真实取值样例  （可裁剪）
L1 业务知识  主题词典 / 指标口径 / 枚举值域 / 禁用字段  （不可裁剪）
L0 系统护栏  角色设定 + 准确性要求                     （不可裁剪）
```

### L2 · 数据画像（**本方案最大单点收益**）

把 `fields_desc` 从一行升级为结构化画像：

```
【字段画像】
- 地区      分类维度 | distinct=8   | 空值率 0%   | 取值: 华东,华南,华北,华中,西南,西北,东北,其他
- 担保类型  分类维度 | distinct=2   | 空值率 0%   | 取值: 融资性,非融资性
- 客户名称  文本标识 | distinct=2143 | 空值率 0%   | ⚠️高基数字段，禁止作为分类维度
- 担保金额  数值指标 | 范围 12万~3.6亿 | 空值率 2.1% | 例: 1250000, 8600000
- 抵押率    【派生指标】= 担保余额 ÷ 抵押物评估价值，比率类，聚合必须用 AVG 不能 SUM
- 身份证号  【禁用】含敏感信息，禁止出现在任何图表中
```

**一次性解决 P1/P2/P3 三个问题**：
- 有了"取值" → LLM 不会编造筛选值（P3）
- 有了"distinct=2143" + "⚠️高基数禁止" → LLM 不会拿客户名称做饼图（P2）
- 有了"【派生指标】口径" → LLM 知道抵押率是算出来的、不能 SUM（P1）
- 有了"【禁用】" → 敏感字段不会进图（合规）

#### 数据来源 —— 比初版估计的更现成（已逐项核实）

| 材料 | 现成位置 | 状态 |
|---|---|---|
| 字段类型 | `FieldAnalyzer` / `schema_enricher` | ✅ 已在用 |
| 业务角色 / chart_hint | `schema_enricher.build_semantics` → `s3_llm_enhancer.py:278-291` | ✅ 已在用 |
| 空值率 | `ai_quality_checker.py:106`、`appendix_service.py:99`、`field_profiles` | ✅ 已算出（D2 归因实查在用） |
| **distinct 计数** | `brain_run_sse.py:1051` `SELECT COUNT(DISTINCT "{_d}")`，入参 `column_cardinality`（`:90`） | ✅ **已算出** |
| **取值样例** | `ai_quality_checker.py:108` `sample_values[:5]` | ✅ **已算出** |
| **现成画像文案模板** | `ai_quality_checker.py:123-127`：<br>`"非空X/Y行, 空值率Z, 唯一值N个, 样例: [...]"` | ✅ **可直接复用** |

**关键结论：Q 需要的材料，链路上几乎全算出来了，只是没喂给 S3。**
初版写的「只需要补 distinct 计数与取值采样」是**低估了现状** —— 它们已经有了。

更值得注意的是 `brain_run_sse.py:1051` 的 DISTINCT：**它是生成之后**才算的，
且只算 `final_charts` 的维度字段（`_d = x_field or category_field`），用途是**事后消毒**
（详见方案 P 的 1.1b 消毒层）。

→ 本方案的核心动作其实是**把这个已经存在的能力前移**：
从「生成后算基数、不合格就丢」变成「生成前把基数告诉 LLM、让它别选错」。
**事前预防比事后丢弃更划算** —— 被丢弃的图不会计入 AI 参与率，预防选对则会。

因此 P0 工作量**低于初版估算的 3 h**：不需要新建画像体系，
主要是把 `ai_quality_checker` 已有的画像计算与文案模板接到 S3 的 `fields_desc` 上。

### L3 · 样本注入（S3 补上，并对齐 S1/S2 的做法）

S1/S2 已经注入 `sample_data[:3]`，**S3 却没有** —— 这是明显的不一致。
补 3~5 行**代表性**样本（不是简单 head，而是覆盖各枚举取值 + 含边界值）。

**必须脱敏**：样本行可能含真实客户名、身份证、手机号。
规则：识别敏感字段（名称/证件/电话/地址类）→ 打码或整列不注入。
**这是把业务数据发给第三方 LLM 的前提，不能省。**

### L4 · 反馈记忆（让系统越用越准）

三类廉价高价值的反馈：
1. **自愈错误**（现成）：`s3_llm_enhancer.py:342` `error_section` 已有 —— 目前只在单次 run 内有效，
   **跨 run 没有沉淀**。可落到 `brain_configs`，下次生成同类数据时前置提醒。
2. **用户修改**：用户手动改了图表字段/类型 → 记下来，下次别再犯
3. **被剔除的图**：方案 P 剔除的图 → 下次该类型/该字段组合降权

### L1 · 业务知识从"词典"升级为"业务词典表"

现在只有主题词典（`brain_configs.theme_dict`）。扩展为四类可运营材料：

| 材料 | 内容 | 谁来维护 |
|---|---|---|
| 主题词典 | 现有能力 | 系统预置 + 管理员 |
| **指标口径** | 抵押率 = 担保余额 ÷ 抵押物评估价值；在保余额 = … | 业务人员 |
| **枚举值域** | 担保类型 ∈ {融资性, 非融资性}；地区 ∈ {八大区} | 业务人员 |
| **禁用字段** | 身份证号、手机号、客户姓名 | 合规 |

**UI 复用现成的 Prompt 中心**（`frontend/src/views/admin/PromptCenter.tsx` 已有增删改查 + 启停能力），
不新做一套管理页面。

### 预算管理：从"粗暴截断"升级为"优先级裁剪"

现状问题：超预算直接砍掉 S4b（`brain_run_sse.py:936-947`），砍的是**整个阶段**，很粗暴。

新策略：**先裁材料，再裁阶段**

```
预算充足   → 全量 L0~L4
80% 告警  → 裁 L4（反馈记忆）
90%       → 裁 L3（样本行）
95%       → L2 画像只保留 distinct>阈值 的字段，去掉"取值"列表
100%      → 才裁阶段（维持现有 S4b 跳过逻辑）
```

并且**要明确告诉 LLM"部分上下文已裁剪，若字段信息不足请只用你有把握的字段"** ——
不让它在信息缺失时硬猜。

### 顺带修的一致性缺口

`brain_run_sse.py:965-983` 的 S4b prompt 是**唯一内联硬编码**的，其余 12 个都在 `prompts/*.md`。
应外置为 `s4b_analysis.md`，与 Prompt 中心体系对齐（否则管理员改不了 S4b 的措辞）。

## 四、验收标准

| # | 断言 |
|---|---|
| V1 | `fields_desc` 输出中含 `distinct=` 与 `空值率`，且高基数字段带"禁止作为分类维度"标注 |
| V2 | 构造含"客户名称"(distinct 2000) 的数据集 → LLM **不再**把它选为饼图分类维度（对比改造前） |
| V3 | 构造含派生指标"抵押率" → prompt 中出现"比率类，聚合必须用 AVG 不能 SUM" |
| V4 | 敏感字段（身份证号）**不出现在任何 prompt 与样本中** |
| V5 | 人为把 TokenBudget 压到 85% → 反馈记忆层被裁、业务知识层**仍在** |
| V6 | 压到 100% → 才跳过 S4b，且日志写明是预算裁剪而非故障 |
| V7 | S4b prompt 改为从 `prompts/s4b_analysis.md` 加载，Prompt 中心可覆盖 |

**V4 是硬红线**：脱敏失败一票否决，不允许先上线再补。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| **数据泄漏**（最大风险）：样本/取值发给第三方 LLM | 敏感字段识别 + 脱敏；禁用字段列表；全量 prompt 落库默认关闭（与方案 O 同一开关） |
| **prompt 变长 → 成本与延迟上升** | 预算优先级裁剪；画像按字段数自适应（字段 >50 时只给高价值字段全画像） |
| **画像本身有误**（如 distinct 统计错）→ 误导 LLM | 画像由数据实算（duckdb COUNT DISTINCT），不靠 LLM 猜；算失败则该字段标"未知"不瞎填 |
| **脱敏过度 → 信息量下降** | 只对识别为敏感的字段脱敏，非敏感字段保留原值 |
| 加了材料反而变差（可能！） | 必须做 A/B 度量（P5），**不许凭感觉说"加了肯定好"** |

## 六、路演价值

1. **"我们不是把数据丢给大模型，而是把数据的结构化理解交给它"** —— 这是与"裸调 GPT"最直接的区别。
2. **业务词典可现场编辑**：评委说"抵押率口径应该是 A ÷ B" → 现场改口径 → 重新生成 → 图立刻变。
   这是"AI 可控"的强证明。
3. **禁用字段**体现合规意识，评委（尤其金融背景）会很在意。
4. 与 O/P 组成完整叙事：
   **Q = 喂什么进去，O = 过程怎么被看见，P = 出来怎么被把关。**

## 七、与其他工作的衔接

- **方案 O**：Q 的注入效果要靠 O 的 `llm_calls` 埋点才能度量（一次通过率、重试次数）；
  Q 的 prompt 摘要落库也复用同一张表
- **方案 P**：Q 在源头减少错误字段（L2 画像），P 在出口拦截（L3 对账）——
  两者是**同一问题的上游解法与下游兜底**，P 的 L2「基数合理」检查与 Q 的「distinct 标注」应共用阈值常量
- **D2（3.5 归因实查）**：字段画像（`null_rate`）已是 D2 的数据源，Q 复用同一份画像，不重复计算
- **`derived_metric_service`**：派生指标口径直接复用其已验证公式，Q 只负责把口径写进 prompt
- **Prompt 中心**：L1 业务词典的 UI 复用现成组件，不新造页面
