| 字段 | 内容 |
|---|---|
| 来源 | B 方案 P0 |
| 依赖 | 无 |
| 估算 | 4~5 h |
| 涉及 | `backend/app/api/brain_run_sse.py`（S3 段 `:719-840`）、`LoadingPage.tsx` |

**子任务**
1. S3 拆两步：先 `S3ChartEngine`（实测 20ms）规则图 → 立即落库看板

3. **删除 `_request_user_choice` 在 S3 失败路径的调用**（`:805-811`）—— 这是消除 5 分钟卡死的关键

**风险**：改动 S3 主流程，是全路线图风险最高的一张票。建议先在一个分支上跑通再合。

## 全局约束（适用所有票）

1. **诚实原则优先于好看**：任何"让 AI 看起来用得更多"的改动都禁止（H4 反方 3/5）
2. **只拦病态，不评判好坏**（H3/T3-2，写进代码注释）
3. **未验证的收益必须明说**：T2-1 在 A/B 出结果前，不得对外宣称"变好了"
4. **监控/检查/注入任何一层失败，都不得阻塞主链路**
5. 每票完成后，把验收脚本**落盘到 `defect_fix_evidence/`**，可复跑（本夜已建立该惯例）
