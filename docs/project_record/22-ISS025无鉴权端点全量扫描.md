# ISS-025 无鉴权端点全量扫描（night19 Task C · 仅扫描方案）

> 生成方式：通过 FastAPI app.openapi() 解析路由表（权威来源），按 operation 是否声明 security 判定未鉴权。
> 扫描结果：总路由 216，未鉴权 131（其中 _internal/test 内部端点与登录/注册/公开分享/健康检查为预期例外）。
> 本文件为扫描 + 分类 + 分批收口建议，不含任何代码改动（Task C 仅扫描出方案，不动码）。

## 二、分类口径

- A-读写用户数据(高危)：无鉴权即可泄露或篡改用户/租户自有数据（看板、报表、会话、token、LLM 用量、会话踢出等）。
- B-内部/系统(中危)：brain/s1~s5 编排、质检、异常检测、血缘、依赖图、触发/恢复、内部测试与调试端点；直接用户隐私风险较低，但应统一收口。
- C-故意未鉴权(保留)：登录/注册/验证码/忘记密码、公开分享查看、健康检查——按既有设计保留匿名访问。

### A 类优先收口建议（Batch 1）
1. 最高危·写类（直接篡改用户数据）：POST /api/v1/chat/execute-action（执行看板增删改！）、POST /api/v1/chat/sessions、POST /api/v1/tokens/consume、POST /api/v1/exceptions/session/kickout/{user_id}。无鉴权即可改动他人看板/会话/令牌——应最先加 Depends(get_current_user) 或等效 guard。
2. 用户隐私读取：GET /api/v1/llm/usage/{user_id}（读特定用户 LLM 用量=PII 泄露）、GET /api/v1/reports、GET /api/v1/golden/*、GET /api/v1/loadtest/*、GET /api/v1/history、GET /api/v1/exports/status/{task_id}——改为需登录或资源归属校验。
3. whitelist 跟踪：以上端点纳入 scripts/auth_whitelist.json，复用既有 scripts/auth_scan.py + scripts/fe_bare_fetch_scan.py 防复发三件套持续核对。
