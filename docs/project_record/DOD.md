# 完成定义（DOD.md）

> 本文件定义"什么算完成"。AI 交付前必须逐条自检。
> 本文件与 `ISSUES.md` 配合：issue 说"做什么"，DOD 说"做到什么程度算完"。
> **本版：v1，2026-09-24。**

---

## 一、什么算"修好一个 bug"？

- [ ] 根因说明（一句话）
- [ ] 改动的文件 + diff
- [ ] 复现命令（我能自己跑一遍）
- [ ] 改前错误现象 + 改后正确现象（**原文粘贴**，不许转述）
- [ ] 本地应用后，我用眼睛能看到区别

**缺任何一条 = 不算修好。**

---

## 二、什么算"完成一个功能"？

- [ ] 代码改了
- [ ] tsc / py_compile 过（EXIT=0）
- [ ] 本地起服务能跑
- [ ] 核心链路能走通（**真点过**，不是"应该能跑"）
- [ ] 未覆盖项明确列出

---

## 三、什么算"完成一个方案"？

- [ ] 根因清楚
- [ ] 改动点具体到 `文件:行`
- [ ] 验证方式说清
- [ ] 风险 / 权衡说明
- [ ] 不需要我追问就能照着做

---

## 四、什么算"完成一次数据操作"（迁移/清理/恢复）？

- [ ] 操作前备份（路径 + 大小，注明）
- [ ] 操作清单（要删 / 改什么，**逐个列**）
- [ ] **用户拍板**（不许自动执行）
- [ ] 操作后前后对比（行数 / 表数 / 文件数）
- [ ] 生产数据完整性验证（关键表可读）

**红线**：任何批量操作前必须备份 + 打印 + 拍板；不许"枚举后循环删"。

---

## 五、什么算"完成一次前端 UI 改动"？

- [ ] `tsc --noEmit` EXIT=0
- [ ] 本地 build 过（`vite build` 0 错误）
- [ ] **真截图**（Playwright / 本机浏览器）
- [ ] 对比修前 / 修后视觉差异
- [ ] 响应式检查（分辨率 1366 / 1920）
- [ ] 暗色模式检查（如适用）

**红线**：UI 改动必须视觉验证，不能只 tsc。

---

## 六、什么算"完成一次 AI 能力修复"？

- [ ] 根因一句话（是 LLM 问题还是代码问题？）
- [ ] 用**失败原句**真跑（不是构造用例）
- [ ] 前后对比：修前 AI 怎么答 vs 修后怎么答（**原文**）
- [ ] 至少 2 个同类场景回归通过
- [ ] 无新回归（其它对话场景仍正常）

**红线**：必须用"用户实际失败的原句"重测，不许用构造用例替代。

---

## 七、什么算"完成一次配置 / 环境改动"？

- [ ] 改动文件 + diff
- [ ] 重启后端（如涉及 `.env`）
- [ ] 启动日志验证（"连的是哪个库 / 端口 / provider"）
- [ ] 真跑一次核心链路（health / 一次生成看板）
- [ ] 影响面说明（影响哪些功能）

**红线**：改 `.env` 必须重启后端；热改不生效。

---

## 八、总原则

1. **证据优先于结论** —— "完成了"必须有可复现的证据
2. **原文优先于转述** —— 错误 / 正确现象必须贴原文
3. **真跑优先于断言** —— "应该能跑" 直接打回
4. **自检优先于交付** —— AI 交付前逐条打勾，不许漏

---

## 九、与 ISSUES.md 的分工

| 文件 | 定义 | 用途 |
|---|---|---|
| `ISSUES.md` | 要做什么 | 问题清单 / 优先级 / 状态 |
| `DOD.md` | 做到什么程度算完 | 交付验收标准 |

**两者配合**：issue 说"修 X 端点"，DOD 说"改前错误 / 改后正确 / 真跑验证"。
