## 一、沟通规则（证据标准）

**踩过的坑**：
- AI 说"修好了" → 你测没好 → 循环
- AI 说"80+ 端点" → 实际 12 个 → 撤回
- AI 说"已提交" → 实际没提交（dangling）
- AI 说"第6张KPI卡片" → 实际只有 2 张

**规则**：

### 规则 1：任何"完成"必须附四样证据
1. 改前的错误现象（原文）
2. 改后的正确现象（原文）
3. 复现命令（我能跑一遍）
4. 动了哪些文件，每个改了什么

缺任何一样 = 不算完成。

### 规则 2：任何数字必须有来源
- "80+ 端点" → 必须给扫描脚本 + 输出
- "12 个" → 必须给清单
- "第6张卡片" → 必须给看板截图
- 拿不出 = 撤回

### 规则 3：任何"应该"直接打回
- "应该生效了" → "跑给我看"
- "应该是环境问题" → "具体是什么？证据呢？"
- "应该没问题" → "验证输出贴我"

### 规则 4：区分"我做了"和"我建议"
- "我做了 X" → 必须附证据
- "我建议做 X" → 明确说是建议，不是执行
- AI 不许把"建议"包装成"已完成"

### 规则 5：无法完成必须诚实说
- "做不到" → 说明原因 + 给替代方案
- 不许"我再试试"就消失
- 不许"模拟一下"充数

## 二、记忆规则（外部记忆）

**踩过的坑**：
- AI 跨会话失忆 → 重复冻结基线、重复建清单
- 状态漂移 → 读旧 status 文件，从错的地方开始
- 上下文丢失 → "新增平均年龄"被丢弃，回到 14 小时前的话题

**规则**：

### 规则 1：每轮开工第一句固定
"先读 `PROJECT_STATUS.md` / `ISSUES.md`，从断点继续。
已完成的不要重做。"

### 规则 2：每完成一项立刻更新
- 从待办划掉
- 移入"已完成"
- 更新"这一轮做什么"
- 不更新 = 下次重做

### 规则 3：状态文件分工
| 文件 | 谁维护 | 用途 |
|---|---|---|
| `PROJECT_STATUS.md` | 我们俩（教练 + 季工） | 进度总表 |
| `ISSUES.md` | 我们俩 | 问题清单 |
| `DECISIONS.md` | 我们俩 | 决策记录 |
| `CHANGELOG.md` | 我们俩 | 变更记录 |
| `ai_action_log` | AI 自己 | 动作日志（10 项） |

### 规则 4：断点续跑协议
- 中断后，先读断点文件
- 已完成的不重做
- 只跑未完成项
- 不许从头开始

### 规则 5：双视图
- 用户视图：血缘 + 清洗结果 + 明细
- AI 视图：`ai_action_log`（10 项完整记录）
- 两个受众，两套视图，不混

### 规则 6：RAG 检索单元分离（新增）
- 文档拆成独立块
- 每块带元数据（module / type / title / source / last_updated）
- Top-K 注入，不是全文注入

### 规则 7：字段语义库（新增）
- AI 推理结果落库（`field_semantics` 表）
- 跨 run 复用，不重复推理
- 用户可纠正

### 规则 8：记忆层 D1-D7（新增）
- 推理 / 决策 / 动作 / 纠正 / 模型元信息
- **模型切换时能承接历史**（关键）

## 三、环境规则（环境自证）

**踩过的坑**：
- 隔离 DB 设了没生效 → 测试全程连生产库
- 多实例（5 个后端进程各指一个库）
- 库路由错（真实表在 qa_aibi.db，后端连 aibi.db）
- 端口残留（8007 被占用，健康检查探活的是残留进程）
- 沙箱限制（缺 libmagic、无 git、下载超时）

**规则**：

### 规则 1：环境起完立刻验证
- 数据库路径是什么？（不是"设了"，是"实际连的"）
- 端口是什么？
- 有几个进程？
- 验证输出贴出来

### 规则 2：隔离必须自证
- 隔离库路径
- 启动日志里连的是哪个文件
- 生产库 mtime 未变
- 三样缺一不可

### 规则 3：单实例
- 启动前查端口占用
- pidfile 守卫（`run_backend.py` B5 已有）
- 残留进程先清

### 规则 4：沙箱限制留痕
- 缺什么（libmagic / git / 网络）
- 影响什么（不能起后端 / 不能 push / 下载超时）
- 替代方案（stub / bundle / 分包）

### 规则 5：收工清理
- 停所有测试服务
- 清理测试数据（DB + 磁盘附件）
- 真实数据前后对比
- 残留说明原因

## 四、规范规则（唯一权威源）

**踩过的坑**：
- 命名乱（AI 生成代码无约束）
- 鉴权散（3 套 require_admin）
- HTTP 客户端两套（fetch + axios）
- 变量名不一致（VITE_API_BASE vs VITE_API_BASE_URL）
- 目录乱（根目录散落文档、night3/4/5 未归位）
- 权限注入无强制检查点

**规则**：

### 规则 1：五类唯一权威源（开工先定 + 现状标注）

| # | 唯一权威源 | 当前真实状态 |
|---|---|---|
| 1 | 身份与鉴权 = `security.py` | ⚠️ 3 套 require_admin，部分统一（3 个 P0 已修） |
| 2 | 网络请求 = `request.ts` | ✅ 已统一（8 裸 fetch 已补） |
| 3 | 配置 = `config.py` | ✅ 已统一（绝对路径化 + fail-fast） |
| 4 | 数据访问 = repository 层 | ❌ 还没做 |
| 5 | 数据模型 = models 层 | ❌ 散落 |

### 规则 2：命名清单（`NAMING.md`）
- 每个模块允许的函数名 / 变量名 / 常量名
- AI 生成代码前先读
- 不符合 → 拒绝提交
- 加 lint 护栏

### 规则 3：权限注入检查点
- 所有用户数据查询必须过 `ownership_filter`
- lint 护栏（AST 检查）
- 测试护栏（越权测试）
- 不可跳过

### 规则 4：目录结构冻结
- `docs/` 下分 `prd/design/api/architecture/test/ops/release/issues/rag_units/`
- 根目录只留 `README/CHANGELOG/RULES/LICENSE`
- 临时产物归档 `_archive/`

### 规则 5：RAG 检索单元分离（已移到"记忆规则 规则6"，此处仅交叉引用）

## 五、协作规则（交接协议）

**踩过的坑**：
- ~~双 agent 分工不清~~（**已作废：新 agent 弃用，单一旧 agent**）
- 你传话丢细节（如果以后有双 agent 才适用）
- 模型切换断链（新模型不知道旧记录）
- 你成了"测试员"（AI 说好了，你去测）

**规则**：

### 规则 1：单一 agent 模式（v1 更新，替代旧"双 agent 分工"）
- **旧 agent**：同时出方案 + 执行 + 自证
- **教练（本对话）**：给提示词 + 判结果 + 维护 `PROJECT_STATUS.md` / `ISSUES.md`
- **你**：拍板 + 本机验收

### 规则 2：结构化交接（如果未来引入新 agent）
- 新 agent 输出：方案（改哪个文件 + 改什么 + 怎么验证）
- 你传递：原文复制，不改一个字
- 旧 agent 执行：贴 diff + 真跑结果
- 新 agent 复核：看 diff 判断对不对

### 规则 3：模型切换承接（如果未来换模型）
- 换模型前：写 `HANDOFF.md`
- 新模型读：`PROJECT_STATUS` + `ISSUES` + `HANDOFF`
- 新模型复述：当前状态 + 下一步
- 确认后才动手

### 规则 4：我不做测试员
- AI 的活：改 + 自证
- 我的活：看证据 + 拍板
- AI 说"好了" → "给四样证据"

### 规则 5：三次上限
- 同一 bug 修 3 次没好 → 停手
- 出完整调用链分析
- 不许"再试一次"

## 七、红线（不可违反）

### 硬红线 6 条（贯穿全程）
1. 禁止任何"批量删除/清理"操作（含"枚举后循环删"、"按条件批量删"）

3. 单个删除操作前：备份 → 打印要删什么 → 用户拍板 → 才执行
4. 改后端鉴权端点，必须同步改前端调用点带 token
5. 改 schema 前必须备份 + 写回滚脚本
6. 每个 commit 前给我看 diff
