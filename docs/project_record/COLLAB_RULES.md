# AI 协作手册（COLLAB_RULES.md）

> 所有 AI（旧 agent / 未来模型）开工前**必须先读本文件**。
> 本文件是"用户 + 教练 + 执行 agent"三方对齐的唯一权威。
> **本版：v3（2026-10-03，对齐 night18 现状 + 新增 §五 规则 7「教练只出提示词」+ 规则 8「每轮更新清单」）。**

## 一、沟通规则（证据标准）

**踩过的坑**：
- AI 说"修好了" → 你测没好 → 循环
- AI 说"80+ 端点" → 实际 12 个 → 撤回
- AI 说"已提交" → 实际没提交（dangling）
- AI 说"第6张KPI卡片" → 实际只有 2 张

**规则**：

### 规则 1：任何"完成"必须附四样证据
1. 改前的错误现象（原文）
2. 改后的正确现象（原文）
3. 复现命令（我能跑一遍）
4. 动了哪些文件，每个改了什么

缺任何一样 = 不算完成。

### 规则 2：任何数字必须有来源
- "80+ 端点" → 必须给扫描脚本 + 输出
- "12 个" → 必须给清单
- "第6张卡片" → 必须给看板截图
- 拿不出 = 撤回

### 规则 3：任何"应该"直接打回
- "应该生效了" → "跑给我看"
- "应该是环境问题" → "具体是什么？证据呢？"
- "应该没问题" → "验证输出贴我"

### 规则 4：区分"我做了"和"我建议"
- "我做了 X" → 必须附证据
- "我建议做 X" → 明确说是建议，不是执行
- AI 不许把"建议"包装成"已完成"

### 规则 5：无法完成必须诚实说
- "做不到" → 说明原因 + 给替代方案
- 不许"我再试试"就消失
- 不许"模拟一下"充数

## 三、环境规则（环境自证）

**踩过的坑**：
- 隔离 DB 设了没生效 → 测试全程连生产库
- 多实例（5 个后端进程各指一个库）
- 库路由错（真实表在 qa_aibi.db，后端连 aibi.db）
- 端口残留（8007 被占用，健康检查探活的是残留进程）
- 沙箱限制（缺 libmagic、无 git、下载超时）

**规则**：

### 规则 1：环境起完立刻验证
- 数据库路径是什么？（不是"设了"，是"实际连的"）
- 端口是什么？
- 有几个进程？
- 验证输出贴出来

### 规则 2：隔离必须自证
- 隔离库路径
- 启动日志里连的是哪个文件
- 生产库 mtime 未变
- 三样缺一不可

### 规则 3：单实例
- 启动前查端口占用
- pidfile 守卫（`run_backend.py` B5 已有）
- 残留进程先清

### 规则 4：沙箱限制留痕
- 缺什么（libmagic / git / 网络）
- 影响什么（不能起后端 / 不能 push / 下载超时）
- 替代方案（stub / bundle / 分包）

### 规则 5：收工清理
- 停所有测试服务
- 清理测试数据（DB + 磁盘附件）
- 真实数据前后对比
- 残留说明原因

### 规则 6：代码目录只放代码，过程文件剥离归位（2026-10-03 用户重申，强制）
- **原则**：`backend/` / `frontend/` 等代码目录**只放运行时代码**；过程文件、产物、台账一律另存，不得混进代码目录。
- **归位表**：

| 东西 | 归哪 | 进 Git？ |
|---|---|---|
| 运行时代码 | `backend/` `frontend/` | ✅ 进 |
| 验证脚本 `_verify_*.py` | `backend/`（项目惯例 gitignored） | ❌ 不进 |
| 轮次报告 / 过程记录 | `docs/project_record/night_runs/` | ❌ 不进 |
| 治理/规范文件（COLLAB_RULES / FACTS / RUNBOOK / CHANGELOG 等） | `docs/project_record/` | ✅ 进 |
| 教练台账 / 复盘（README 锚点 / 轮次总账 / ISS 债 / 决策记录 / 功能矩阵） | OneDrive `待整理信息/ai快速报表/` | ❌ 不进（项目外） |
| 临时产物 / 归档 | `_archive/` | ❌ 不进 |

- **提交前必问一句**：这个文件是"代码"还是"过程"？**是过程 → 先归位，再提交**。
- **禁止**：把过程文件 / 临时脚本 / 台账塞进代码 commit；禁止一个 commit 里混"代码 + 过程"。
- **依据**：D-016（过程文件剥离）+ D-023（验证脚本 gitignored）+ 用户 2026-10-03 重申（原话"保持代码文件清晰，过程文件另外存"）。

## 五、协作规则（三角色分工）

**踩过的坑**：
- ~~双 agent 分工不清~~（**已作废：新 agent 弃用，单一旧 agent**）
- ~~你成了"测试员"~~（AI 说好了，你去测）→ 改为 AI 自证 + 你只做本机验收
- 模型切换断链（新模型不知道旧记录）
- 教练越位写代码 → 教练只出提示词/判结果，不碰代码（v2 明确）

**规则**：

### 规则 1：三角色分工（v3 定稿，替代 v1"单一 agent 模式"）
| 角色 | 干什么 | 不干什么 |
|---|---|---|
| **用户（季工）** | 拍板 + 本机验收 + 传话（原文复制） | 不做测试员、不写提示词 |
| **教练（本对话）** | 复盘 + 界定职责 + 写提示词（含背景/目标/边界/验收）+ 抽验证据 + 判结果 + 维护 `PROJECT_STATUS.md` / `ISSUES.md` / `AI_CHANGES.md` 台账 | **不写业务代码、不亲自跑长命令/刷日志**（只出方案/提示词/抽验） |
| **执行 agent** | 编码执行 + 自证 + 贴 diff + 真跑结果 + 登记 `AI_CHANGES.md` | 不擅自扩大范围、不跳过红线 |

### 规则 7：教练只出提示词，执行由"用户的 agent"完成（2026-10-03 用户拍板，强制）
- **分工**：**教练（本对话）= 指挥 + 大脑决策 + 抽验**；**执行 = 用户自己的 agent**（用户把教练给的提示词**原文粘贴**给它跑）。
- **闭环（一轮一循环）**：教练出提示词 → 用户原文转交其 agent → agent 执行并交四样证据（§一）→ 用户原文回传 → 教练抽验 → 放行/打回 + **出下一轮提示词**。
- **禁止**：教练亲自改业务代码、亲自跑脚本/长命令/刷日志；教练也**不代替用户在其环境里执行**（不越位）。
- **教练提示词必须可直接粘贴**，且含五要素：**背景 / 目标 / 边界（红线）/ 验收方式（四样证据）/ 交付格式**。
- **排满任务**：一轮提示词里可给 agent 排**多个互不冲突**的任务以加快进度；但**同文件改动必须串行**，避免互相覆盖。
- **抽验**：教练对回传证据至少复跑一次关键命令，或核对 diff 关键行；不合规直接打回。

### 规则 8：教练每轮文档更新清单（2026-10-03 定，防"换 agent 就失忆"）
**每轮 agent 回证 + 教练抽验后，教练按序更新以下 5 件（用户零操作）：**

| 序 | 文件 | 更新什么 | 时机 |
|---|---|---|---|
| 1 | `AI-Report 项目 README（教练记忆锚点）` | 现状 / 路线 / 活跃卡点 / 事实（**只放当前真值**） | 每轮第一件 |
| 2 | `轮次总账 ROUND_LEDGER` | 本轮一节：目标 / 改动 / commit / 证据 / **验收结果** / 遗留 | 每轮收尾 |
| 3 | `ISS 债跟踪文档` | 活跃问题状态翻转 + 新登记 + 待拍板 | 每轮 |
| 4 | `决策记录` | 新拍板（新增 D-xxx 或修订演变列） | 有新拍板时 |
| 5 | `功能完成度 × 验收矩阵` | 功能完成状态 / 用户验收列 | 功能状态变化时 |

- **锚点纠偏优先**：发现锚点写的是过期/矛盾事实 → **先改锚点**（锚点错 = 新 agent 读错前提，比没文档更危险）。
- **源与镜像**：项目内 `docs/project_record/` 为权威源，OneDrive 为镜像，两侧内容必须一致。
- **恢复口令（开工必读 5 步）**：README 锚点 → ISS 债跟踪 → 决策记录 → 功能完成度矩阵 → 轮次总账。
- **验收结果不可代填**：用户验收列只能由用户本机确认后改 ✅，教练不得代填。

### 规则 2：结构化交接（跨 agent / 跨模型）
- 教练输出：提示词（含背景 + 目标 + 边界 + 验收方式）
- 用户传递：**原文复制，不改一个字**
- 执行 agent：贴 diff + 真跑结果 + `AI_CHANGES.md` 登记
- 教练复核：看 diff 判断对不对，不对则打回

### 规则 3：模型切换承接（换模型时）
- 换模型前：更新 `handover/`（当前状态 + 待办 + 坑位）
- 新模型读：`COLLAB_RULES` + `PROJECT_STATUS` + `ISSUES` + `handover/README`
- 新模型复述：当前状态 + 下一步 → 确认后才动手

### 规则 4：用户不做测试员
- AI 的活：改 + 自证（四样证据）
- 用户的活：看证据 + 拍板 + 本机验收
- AI 说"好了" → "给四样证据"

### 规则 5：三次上限
- 同一 bug 修 3 次没好 → 停手
- 出完整调用链分析
- 不许"再试一次"

### 规则 6：一 commit 一类改动（night13 起固化）
- 一类一 commit + 一类一 push；失败立即 `git revert`
- commit 前必须给用户看 diff
- commit 信息关联 ISS 编号 / Task 编号
