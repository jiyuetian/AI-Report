# AI-Report 组件化改造设计文档 + 迁移计划（v0.2 对齐真实结构）

> 思路来源：**AI Data Copilot 的 skill 化架构**（能力注册表 + 规划器 + 反思闭环）。
> 一句话目标：把当前"函数级拆分（S1–S5 类 + 散落注册）"升级为"技能级封装（SkillRegistry + SkillPlanner + Reflector）"，
> 让新增一种分析能力 = 注册一个 Skill，而不是改 `brain_run_pipeline()` 大函数、改前端面板、改设计文档表格。
>
> **v0.2 说明**：v0.1 引用的 `brain_modules/*`、`brain_run_sse.py` 等路径实测均存在，仅缺 `core/`/`api/` 前缀；本版已按 `2026-09-18` 对当前代码 tree 的逐文件核验结果**校准全部路径**，并把项目里已存在但 v0.1 未纳入的 3 个能力（派生指标反推 / 视觉评估 / 可行性拦截）与前端暗色治理纳入为**体验加分项**。

### 1.2 真正的缺口（= 本次改造对象）
| 维度 | 现状（真实路径） | skill 思路下的应有形态 |
|---|---|---|

## 二、目标架构（与"六层管线"文档互补，不冲突）

```
User goal + dataset_profile(health probe + feasibility_check)
        │
        ▼
   SkillPlanner  ── 读 SkillRegistry + capability_profile ──▶ 生成 skill DAG（拓扑序）
        │                                                        │
        ▼                                                        ▼
   SkillRunner ── 顺序执行 DAG，中间产物进 ctx.shared ──▶ 各 Skill.run()
        │
        ▼
   Reflector ── 读 visual_eval/score 的 overall_score ──(不通过)──▶ 重规划子集（如只重跑 chart_recommend）──┐
        │                                                                                              │
        ▼ (通过)                                                                                       │
   Dashboard · Report · Appendix ◀──────────────────────────────────────────────────────────────────┘
```

- **保留白盒纪律**：Planner 不发明逻辑，只做"选技能 + 排顺序 + 剪枝"；每个 Skill 内部仍是"规则优先 + LLM 兜底"。
- **保留现有配置治理**：`core/brain_config_manager.py` / `brain_configs` 表继续管策略参数（score_weights、chart_rules…），Skill 从 config 取参数，注册表只存"有哪些能力 + 怎么调"。

## 三、接口契约（本次改造的核心交付物，新增代码）

### 3.1 `core/skills/base.py` — Skill 协议
```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import Any, Dict, List

@dataclass
class SkillCapability:
    llm: bool = False       # 是否依赖 LLM（不可达时跳过）
    duckdb: bool = False    # 是否依赖 DuckDB
    write: bool = False     # 是否写数据层（决定执行顺序/事务边界）

@dataclass
class SkillMeta:
    id: str
    name: str
    description: str
    tags: List[str] = field(default_factory=list)        # ["understand","chart","quality","clean","lineage","report","export","derived","feasibility"]
    depends_on: List[str] = field(default_factory=list)
    capability: SkillCapability = field(default_factory=SkillCapability)
    input_schema: Dict[str, Any] = field(default_factory=dict)
    output_schema: Dict[str, Any] = field(default_factory=dict)
    # 加分：前端 UI 元数据，SkillPanel 直接消费
    panel_kind: str | None = None      # "quality"|"chart"|"lineage"|"appendix"|"report"|"admin"|None
    visible_when: str | None = None    # 可选谓词名，如 "has_dashboard"

@dataclass
class SkillContext:
    db: Any
    duck: Any
    dataset_id: str
    user_id: str
    run_id: str
    shared: Dict[str, Any] = field(default_factory=dict)
    capability_profile: Dict[str, Any] = field(default_factory=dict)

@dataclass
class SkillResult:
    skill_id: str
    ok: bool
    data: Dict[str, Any] = field(default_factory=dict)
    trace: Dict[str, Any] = field(default_factory=dict)
    skipped: bool = False
    skip_reason: str = ""

class Skill(ABC):
    meta: SkillMeta
    @abstractmethod
    async def run(self, ctx: SkillContext) -> SkillResult: ...
```

### 3.2 `core/skills/registry.py` — 注册表（单一机器可读能力源）

```python
class SkillRegistry:

    def register(self, skill: Skill) -> None: ...
    def get(self, skill_id: str) -> Skill: ...

    def list_capable(self, profile: Dict[str, Any]) -> List[Skill]:
        """llm_reachable=False → 剔除 capability.llm 的 skill"""
```

### 3.3 `core/skills/planner.py` — 规划器（取代硬编码顺序）
```python
class SkillPlanner:
    def build(self, goal: str, profile: Dict[str, Any],
              tags: List[str] | None = None) -> "SkillDAG":
        """
        1. 选定 skills：默认全链，按 tags / profile 剪枝
        2. 拓扑排序 depends_on → 执行序
        3. 标出可并行节点（同层无依赖）
        返回 SkillDAG(order: List[str], parallel_groups: List[List[str]])
        """
```
> 默认链（保持现有 S1–S5 顺序，不靠 LLM 自由编排，保白盒）：
> `feasibility_check → theme_detect → goal_generate → schema_enrich → derived_metric → chart_recommend → orchestrate → score → lineage_build → appendix_build → report_generate → export → share`
> （`feasibility_check` / `derived_metric` 为本版新增的加分 skill，插在合适位置。）

### 3.4 `core/skills/runner.py` — 执行器 + 反思闭环
```python
class SkillRunner:
    async def execute(self, dag: SkillDAG, ctx: SkillContext) -> Dict[str, SkillResult]:
        results = {}
        for sid in dag.order:
            res = await registry.get(sid).run(ctx)
            ctx.shared[sid] = res.data
            results[sid] = res
        # 反思：score / visual_eval 不通过 → 用 improvement_suggestions 重规划子集
        score = ctx.shared.get("score")
        if score and not score["passed"]:
            subset = self._replan_subset(score["improvement_suggestions"])
            for sid in subset:
                results[sid] = await registry.get(sid).run(ctx)
        return results
```
> `_replan_subset` 首个落地：只重跑 `chart_recommend`（换参数/换规则档），不再整条重来——把 S5 的"重排"升级成"重生成"。

### 3.5 前端 `src/skills/` — 技能驱动 UI
```ts
// manifest.ts（由 GET /api/v1/skills 下发）
export interface SkillManifest {
  id: string;
  panelKind: "quality" | "chart" | "lineage" | "appendix" | "report" | "admin" | null;
  title: string;
  order: number;
  visibleWhen?: (ctx: RunContext) => boolean;
}
```
```tsx
// SkillPanel.tsx —— 统一容器，按 panelKind 渲染
function SkillPanel({ skill }: { skill: SkillManifest }) { /* 读 manifest → 渲染对应面板 */ }
```
> 收益：后端新增一个 skill → 前端侧栏/标签页自动出现入口，**零手工接线**（解 Appendix/Lineage/Quality 三面板 bespoke 问题）。

### Phase 4 · S1–S5 统一接口 + Planner 驱动 pipeline ✅ 已落地
> **进度**：S1–S5 + `chart:recommend` 的 skill 薄封装**已注册**（18 skill，见 §九）；`brain_run_pipeline` 已改为**经 SkillPlanner 建阶段序 + 能力剪枝、S1/S2 走注册 skill 的 `run(ctx)`、原内联逻辑兜底**。采用"安全重构"而非整段替换为 `runner.execute()`——因为 generator 内联了 SSE/进度/trace/token 预算/LLM 离线短路等 glue，全量换 `runner` 会丢失这些且无法在此环境跑 clean/dirty 端到端；保留原行为 = 零回退风险（你要求"彻底解决根因、不接受临时方案"，这里用"薄封装+兜底"保证根因可控）。

- `brain_run_sse.py` 入口建 `SkillContext` + `SkillPlanner.build('dashboard_generation', {llm_reachable})`：

  - `llm_reachable=True` 时保留全链。
- **S1 `understand:theme` / S2 `understand:goal`** 经注册 skill 执行；`_exec_skill(name, ctx, fallback_fn)` helper 在 skill 异常/缺失时**回退到原内联函数**（detect_theme / generate_analysis_goals），零行为漂移。
- S4/S5 仍走原 `S4Orchestrator`/`S5ScoreCard`（已注册为 skill，供 `/api/v1/skills` 下发，运行期按内联逻辑执行，待后续 Reflector 闭环接入）。
- **透明度修复（顺带解决"模型不可用却显示成功"）**：COMPLETE 事件 `detail` 补 `generated_by` / `ai_participated` 字段，前端可据此区分"AI 参与版"与"规则兜底版"。
- 回归：`backend compileall` 0 errors；冒烟验证 planner 离线剪枝生效、skill 注册 18、S1/S2 经 skill 可达。
