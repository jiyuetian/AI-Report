## 关键发现（本项最大价值）

### 实测：最坏会卡 5 分钟，不是我以为的 1 分钟

`verify_32_current_state.py` 跑出来的真实配置：

| 项 | 值 |
|---|---|
| `BRAIN_S3_LLM_TIMEOUT` | **180.0 秒**（`config.py:54`） |
| 用户决策等待 `_request_user_choice` | 120 秒（默认） |
| **最坏总耗时** | **300 秒 = 5.0 分钟** |

`brain_run_sse.py:805-811`：S3 的 AI 一旦失败就**暂停流水线弹框问用户**
「用规则兜底 还是 等 AI 恢复重试」。

→ 我初版方案写"等 30~60 秒"**低估了 3~6 倍**，已更正。
→ **路演灾难场景**：LLM 抽风 → 加载页卡 5 分钟 + 中途弹框让主持人做选择。
→ 这也重新定位了方案 C：**它不是体验优化，是风险消除。**

### 实测：规则引擎毫秒级（方案 C 的前提成立）

16 字段 × 20 次：平均 20.7ms / P50 15.7ms / P95 68.3ms，产出 6 张图。
且 `s3_chart_engine_v2.py` 全文 `conn.execute` 0 次、`duck` 0 次 → 纯内存。

**对比：规则图 20ms vs 最坏 300,000ms —— 相差 1.5 万倍。**

### 版本表可承载升级

`DashboardVersion` 有 `config_snapshot` / `version_number` / `is_auto_save` / `prompt_version`，
且已有 `backend/app/core/version_manager.py` 写入路径 → 规则版 v1 + AI 增强版 v2 + 回滚，天然可行。

## 设计上的三个关键取舍

1. **默认"追加"而非"替换"** —— 规则图已在用户眼前，突然被换掉会造成困惑
2. **冲突检测必备** —— 用户在增强完成前改了看板 → 存 v2 但不覆盖，提示去版本历史看
3. **失败静默** —— 不弹框不阻塞，只在看板页显示一行灰字说明"AI 增强未完成"
