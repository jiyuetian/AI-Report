# 方案 P · AI 结果检查（★ 核心）

> 目标：从"AI 输出格式对不对"，升级到"AI 输出的**内容**对不对、能不能和数据对账"。
> 核心价值词：**反幻觉（anti-hallucination）** —— 数值必须与真实数据算出来的一致，否则不许上图。

### 1.3 ⚠️ 一个正在发生的 bug（本方案必须顺带修）

## 二、方案设计：三层检查（Check Ladder）

```
L3 事实层 ── 数值对账：AI 说的数 = 数据实算的数？      ← 本方案核心新增
L2 语义层 ── 字段/粒度/基数/类型：图能不能画出来？      ← 已有一半，补全 + 修 bug
L1 语法层 ── jsonschema：结构对不对？                  ← 已有，扩展到 S1/S2/S4b
```

### L1 · 语法层（扩展）

给 S1/S2/S4b 各加一个轻量 schema：

| 阶段 | 校验什么 |
|---|---|
| S1 | `theme` 非空且在候选集内（或说明是新增主题）；`confidence ∈ [0,1]` |
| S2 | `goals[].name` 非空；`goals[].chart_types[]` 必须是白名单内的类型码 |
| S4b | 输出必须是非空文本，长度 ∈ [20, 2000]，且**不得包含占位符**（`TODO`/`待补充`/`xxx`）；文本中的数字须通过事实对账（见 L3 文本对账） |

### L2 · 语义层（补全）

对每张图（不只是 S3 批次整体）：

| 检查项 | 判据 | 处置 |
|---|---|---|
| 字段存在 | 用**归一化**匹配（修 1.3 的 bug） | 自动修正为最相近真实字段 |
| 类型兼容 | y/value 必须是数值型；x 若是趋势图必须是日期型 | 自动换字段或降为 table |
| **基数合理** | 分类字段 distinct 数：饼图 ≤12、柱状 ≤30、超过则病态 | 自动取 Top-N + "其他" |
| **空值率** | 字段 null_rate ≥ 0.999 → 画出来是空图 | 剔除该图，记为 `emptied` |
| 粒度冲突 | 已有（macro 禁明细表） | 保留 |

> 「基数合理」「空值率」两项现在**完全没有**，但它们恰恰是"图能画出来但没意义"的主因。
> 且空值率判定与 D2（3.5 归因实查）的 `_diagnose` 四类判定**完全相同**，应共用同一函数。

### L3 · 事实层（核心新增 —— 反幻觉）

**原理**：把 AI 产出的图表配置**真正执行一遍聚合**，与数据实算值对账。

```
AI 输出："总担保金额" KPI，metric=担保金额，agg=sum
   ↓
实算：SELECT SUM("担保金额") FROM dataset   →  1,234,567,890
   ↓
对账：AI 展示值 == 实算值？  →  ✅ 一致 / ❌ 不一致（幻觉）
```

**对账矩阵**：

| 图类型 | 对账内容 | 不一致判据 |
|---|---|---|
| KPI | `agg(metric)` 实算 vs 卡片值 | 相对误差 > 0.5% |
| 柱状/饼图 | 各分类实算值 vs 图表 series | 任一类相对误差 > 1% |
| 折线 | 各点实算值 vs series | 同上 |
| 表格 | 行数、列值抽样 | 行数差 > 5% |
| **派生指标**（如抵押率） | 用**已验证公式**实算（现成：`derived_metric_service`） | 比率类必须用 AVG 不能 SUM |

### L3 补充 · 文本对账（S4b 分析说明）

初版只写了"占位符检测"，这是**空缺** —— S4b 生成的分析说明里往往带具体数字
（"担保金额合计 12.3 亿元，同比增长 18%"），这些数字同样可能是幻觉。

**解法：从文本中抽取数字，与数据实算对账**

```
1. 正则抽取文本中的数值片段（支持 12.3亿 / 1,234万 / 18% / 1234.56）
2. 对每个数值，在"本次生成的图表实算结果集合"里找可匹配项
   - 金额类 → 与各 KPI 实算值比对（相对误差 ≤1% 视为命中）
   - 百分比 → 与占比类图表的实算占比比对
3. 三类结论：
   - matched   ：能在实算结果中找到对应值 → ✅
   - unmatched ：找不到对应值 → ⚠️ 标"该数值未与数据对账"，图上/文上做弱化提示
   - contradicted：与实算值冲突（如文本说 12.3 亿，实算 9.8 亿）→ 🔴 必须处理
```

**处置**：`contradicted` 时**不静默改用户要读的文字**（改文案风险高），
而是：① 在说明区加一行灰色小字「文中数值与数据实算不一致，实算值 9.8 亿元」；
② 记入 `llm_calls.error_code = text_contradicted` 供统计。

**为什么不一刀切**：文本对账有天然误判率（四舍五入、单位换算、区间表述），
**宁可标"未对账/不一致"让人判断，也不要偷偷改写 AI 的措辞** —— 与 2.1 诚实原则一致。

**关键设计**：对账用**同一份数据、同一套聚合口径**，不引入第二个"真相源"。
若实算失败（字段被删/数据集变了），结论标 `unknown` 而**不是** `pass` —— 与 2.1 诚实原则一致。

**处置策略（重要）**：不一致时**不一律删除**，分三档：

| 档 | 情形 | 动作 |
|---|---|---|
| A 可自动修正 | KPI 数值与实算不符，但字段/口径正确 | **用实算值覆盖** AI 值，标记 `auto_corrected`（图上标"数值已与数据对账校正"） |
| B 可降级保留 | 分类基数过大 | 取 Top-N + 其他，标 `downgraded` |
| C 必须剔除 | 字段不存在且找不到相近字段 / 字段全空 | 移除该图，在看板底部列出"已剔除 N 张图及原因" |

**为什么不一删了之**：全删会让看板变空、AI 参与率归零，反而更糟。
A 档"用实算值覆盖"是最优解 —— **AI 负责选题和构图（它擅长的），数值由数据说了算（它不该编的）**。

## 三、检查结果落库与展示

**落库**：`brain_traces.stage_output` 增加 `check_result` 字段，以及看板 config 每图增加：

```json
{
  "title": "总担保金额",
  "chart_type": "kpi",
  "generated_by": "llm",
  "check": {
    "level": "L3",
    "status": "pass",            // pass | auto_corrected | downgraded | removed | unknown
    "reconciled": true,
    "expected": 1234567890,
    "actual": 1234567890,
    "msg": "与数据实算一致"
  }
}
```

**展示**：每张图右上角一个体检徽标（Tooltip 展开明细）

| 徽标 | 含义 |
|---|---|
| 🟢 已对账 | L3 通过，数值与数据一致 |
| 🔵 已校正 | L3 发现偏差，已用实算值覆盖 |
| 🟡 已降级 | 基数过大等，已做处理 |
| 🔴 已剔除 | 不达标（并在底部列表说明原因） |
| ⚪ 未对账 | 实算失败或该类型暂不支持对账（**不许显示成绿**） |

**看板级汇总**：「AI 生成 5 张图 · 已对账 4 · 已校正 1 · 剔除 0」。

## 五、验收标准

| # | 断言 |
|---|---|
| V1 | 字段名带首尾空格（`" 抵押率 "`）时，`validate_grain_compatibility` 判 **通过**（当前判失败，已由 repro 脚本实测确认） |
| V2 | 让 LLM 故意返回一个不存在的字段 → 检查器给出 `字段不存在` 且**尝试自动修正**为最相近真实字段 |
| V3 | 构造一个 KPI 值与实算差 20% 的用例 → 检查器标 `auto_corrected`，看板显示**实算值** |
| V4 | 分类字段 distinct=2000 做饼图 → 自动降级 Top-N + 其他，标 `downgraded` |
| V5 | 字段 null_rate=1.0 → 该图被剔除，看板底部列出原因 |
| V6 | 实算失败（数据源不可达）→ 标 `unknown`，**不许标 pass** |
| V7 | 全部分类字段正常时，检查器不产生任何误剔除（防过度检查） |

V1 与 V7 是**双向验收**：V1 防假阴性（错杀好答案），V7 防假阳性（过度检查）。
只做一边都会把系统搞坏 —— 这与我在 D2 深度补充里补「用例11 防假阳性」是同一个道理。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| **实算开销**：每张图都跑一次聚合，大表变慢 | 复用已加载的 duckdb 数据集；只在生成阶段跑一次；结果随图缓存 |
| **对账口径不一致**：AI 用 AVG、实算用 SUM | 比率类派生指标强制 AVG（`derived_metric_service` 已有该口径），口径写在图的 `check` 里可追溯 |
| **过度检查导致看板变空** | 三档处置（A 校正 / B 降级 / C 剔除），剔除是最后手段；V7 防误剔除 |
| 浮点比较误差 | 用相对误差阈值（KPI 0.5%，分类 1%），不用精确相等 |
| 检查器自身有 bug 会放大错误（1.3 就是实例） | 检查器要配自己的单测（V1~V7 全部写成测试） |

## 七、路演价值

1. **"AI 不许编数字"是最能打动评委的一句话**，而且是可演示的：
   现场把某个 KPI 的真实值改掉 → 重新对账 → 图上立刻标"已校正"。
2. **敢展示"已剔除"**：看板底部如实列出"AI 生成了 6 张，剔除 1 张（原因：字段全空）"——
   证明系统有把关，而不是照单全收。
3. 与方案 O（过程监控）合成完整闭环：
   **O 回答"AI 干了什么"，P 回答"AI 干得对不对"**。
4. 反幻觉是当下评委最关心的点之一，而绝大多数参赛项目只做格式校验 —— 事实层对账是硬差异化。
